# Управление парком велосипедов с помощью REINFORCE

Лабораторная по обучению с подкреплением (RL). Агент каждое утро решает, сколько велосипедов держать на улицах, а спрос берётся из реальных данных проката.

## Зачем нужен проект

Если велосипедов мало, клиенты уходят. Если их много, лишние велосипеды стоят без дела, но за них приходится платить. Перевозка тоже стоит денег, а спрос заранее неизвестен.

Цель работы: обучить агента REINFORCE управлять парком и проверить, приносит ли он больше прибыли, чем простые правила.

В отличие от задачи FrozenLake с табличным Q-learning, здесь нет таблицы значений Q. Небольшая нейросеть получает числовые признаки и сразу выдаёт вероятности действий.

## Как запустить

Нужен только Docker. Команды выполняются из корня проекта.

**1. Собрать образ.** При сборке скачивается и обрабатывается датасет, поэтому нужен интернет:

```bash
docker build -t bike-rl .
```

**2. Запустить обучение и создать отчёт:**

```bash
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/outputs:/app/outputs" bike-rl
```

**3. Открыть отчёт** `outputs/report.html` в браузере.

На 16-ядерном процессоре запуск занимает около 1,5 минуты, на компьютере с меньшим числом ядер обучение идёт дольше. Видеокарта не нужна.

Команды написаны для Linux, macOS и WSL. В Windows PowerShell вторая команда выглядит так:

```powershell
docker run --rm -v "${PWD}/outputs:/app/outputs" bike-rl
```

## Датасет

[Bike Sharing Dataset (UCI)](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset), файл `day.csv`: дневная статистика проката Capital Bikeshare (Вашингтон) за 2011–2012 годы, 731 день.

| Колонки | Значение | Как используются |
|---|---|---|
| `cnt` | Число аренд за день | Спрос в среде. Агент узнаёт его только после решения |
| `temp`, `hum`, `windspeed` | Температура, влажность, ветер (нормированы) | Состояние агента |
| `weathersit` | 1 — ясно, 2 — облачно, 3 — дождь или снег | Три флага в состоянии агента |
| `workingday`, `holiday` | Рабочий день, праздник | Состояние агента |
| `casual`, `registered` | Аренды по типам клиентов | Агент их не получает: они раскрывают сегодняшний спрос |

Что делает `prepare_data.py`:

- сверяет контрольную сумму архива;
- проверяет отсутствие пропусков, повторов дат и пропущенных дней, а также равенство `cnt = casual + registered`;
- добавляет вчерашний спрос, средний спрос за 7 дней, время года и флаги погоды;
- удаляет первые 7 дней без полной истории спроса, остаётся 724 дня;
- разделяет данные по времени.

| Часть | Период | Дней | Назначение |
|---|---|---|---|
| Обучение | 08.01.2011 – 31.03.2012 | 449 | Обучение агента |
| Валидация | 01.04.2012 – 30.06.2012 | 91 | Выбор лучших весов и `gamma` |
| Тест | 01.07.2012 – 31.12.2012 | 184 | Итоговая оценка |

Полный EDA с графиками находится в отчёте. Главное из него:

- средний спрос в 2012 году в 1,63 раза выше, чем в 2011-м, поэтому данные разделены по времени;
- спрос сильно зависит от сезона и погоды и слабо зависит от типа дня;
- 29.10.2012 (ураган Сэнди) было всего 22 аренды. Этот выброс оставлен в тесте;
- один день имеет влажность 0%. Это похоже на ошибку записи, но строка оставлена без изменений.

## Постановка RL

| Элемент | Описание |
|---|---|
| Шаг | Один день |
| Состояние | 15 чисел: парк, разница парка со вчерашним и средним спросом, вчерашний и средний спрос, температура, влажность, ветер, рабочий день, праздник, 3 флага погоды, 2 числа времени года |
| Действие | Изменить парк: -1000, -250, 0, +250 или +1000 велосипедов |
| Прибыль за день | `1 × обслуженные аренды − 0.3 × парк − 0.1 × перевезённые велосипеды` |
| Награда | `(прибыль − 0.7 × спрос) / 1000`, то есть потери относительно идеального дня |
| Эпизод при обучении | 60 дней со случайной даты и со случайным стартовым парком |
| Эпизод при проверке | Все дни периода |

Цены условные, в датасете их нет. Для простоты один велосипед обслуживает одну аренду в день.

### Пример одного дня

На улицах 5000 велосипедов, агент выбирает +250, парк становится 5250. Спрос оказался 6000, поэтому обслужено 5250 аренд.

- Прибыль: `5250 − 0.3 × 5250 − 0.1 × 250 = 3650`.
- Идеальная прибыль: `0.7 × 6000 = 4200`.
- Награда: `(3650 − 4200) / 1000 = −0.55`.

## Как работает REINFORCE

Нейросеть состоит из одного скрытого слоя: `15 входов → 64 нейрона (Tanh) → 5 выходов (softmax)`. На выходе получаются вероятности пяти действий.

Один шаг обучения:

1. Агент проходит 16 эпизодов и выбирает действия случайно по своим вероятностям.
2. Для каждого дня считается `G_t = r_t + gamma * r_(t+1) + gamma^2 * r_(t+2) + ...`.
3. Значения `G_t` нормируются: важно, лучше или хуже среднего сработало действие.
4. Вероятность действий с результатом выше среднего растёт, а с результатом ниже среднего падает.

Всего 600 шагов обучения. Проверяются значения `gamma` 0, 0.9 и 0.99, каждое на 5 сидах. При проверке агент выбирает самое вероятное действие.

**Почему награда — это потери, а не прибыль.** Летом прибыль высокая почти при любых действиях, поэтому агент получал бы высокую оценку за сезон, а не за хорошее решение. Идеальная прибыль не зависит от действий, поэтому её вычитание не меняет лучшую стратегию, но убирает часть сезонного шума.

## Результаты

Прибыль на тесте за 184 дня:

| Стратегия | Прибыль, тыс. у. е. | Потерянный спрос | Простой парка |
|---|---:|---:|---:|
| **REINFORCE** (среднее по 5 сидам) | **716,5 ± 2,4** | 2,7% | 10,6% |
| Как средний спрос за 7 дней | 697,6 | 6,5% | 8,0% |
| Как вчерашний спрос | 696,6 | 5,7% | 8,0% |
| Постоянный парк (7000) | 686,9 | 3,5% | 16,7% |
| Случайные действия | 612,1 | 4,9% | 27,3% |
| Предел: парк равен спросу, перевозки бесплатны (недостижим) | 778,3 | 0% | 0% |

Все 5 запусков агента обогнали лучшее правило. Результаты повторяются при новом запуске на том же компьютере, потому что сиды зафиксированы.

**Выбранное значение `gamma = 0`.** Оно показало лучший результат на валидации: 372,1 против 369,0 при `gamma = 0.9` и 370,9 при `gamma = 0.99`. На тесте порядок такой же: 716,5, 705,1 и 710,2, но для выбора тест не использовался. При `gamma = 0` агент при обучении учитывает только награду текущего дня и не учитывает влияние решения на следующие дни. Среда при этом остаётся последовательной: сегодняшний парк переходит на завтра и входит в состояние. Вероятное объяснение: прибыль дня сильно зависит от парка в этот же день, а завтра парк можно снова поправить. Отдельным экспериментом это не проверялось.

Перед защитой стоит учесть:

- **Идеальный прогноз погоды.** Агент видит фактическую погоду текущего дня, а простые правила её не используют. Часть преимущества может объясняться этим допущением.
- **Условные цены.** При других значениях результат может измениться.
- **Тест смотрели до доработки.** Первая версия с прибылью в качестве награды получила на тесте 680,1 ± 28,5. Настройки затем сравнивались только на валидации, но первый результат на тесте был уже известен.
- **Один тестовый период.** Проверка охватывает только второе полугодие 2012 года.

## Как изменить настройки

- Параметры обучения находятся в начале `src/train.py`: `UPDATES`, `EPISODES_PER_UPDATE`, `GAMMAS`, `SEEDS`.
- Цены и действия находятся в начале `src/env.py`: `PRICE`, `BIKE_COST`, `MOVE_COST`, `ACTIONS`.

После изменений образ нужно собрать заново.
