# MELD: Multimodal Emotion and Sentiment Recognition

Мультимодальная нейросеть для распознавания **эмоций и тональности речи (sentiment)** по текстовым и аудиоданным с использованием **Cross-Attention** и **Multi-Task Learning (MTL)**.

Проект разработан в рамках лабораторных работ по глубокому машинному обучению и объединяет два подхода:

- **Cross-Attention** — взаимодействие текстовой и аудиомодальности с помощью механизма перекрёстного внимания.
- **Multi-Task Learning** — одновременное обучение модели двум задачам: классификации эмоций и определению тональности высказывания.

Для реализации используются Python, PyTorch, Hugging Face Transformers (RoBERTa), NumPy, SciPy и Docker. Обучение выполняется на GPU (CUDA).

## 1. Описание проекта

Цель проекта — построить модель, способную определять эмоциональное состояние человека на основе произнесённой реплики и её звучания.

Использование только текста не всегда позволяет правильно определить эмоцию. Например, одна и та же фраза «I'm fine» может произноситься спокойно, раздражённо или с грустью. Поэтому в модели объединяются две модальности:

- **Текст:** слова и их семантические представления.
- **Аудио:** акустические характеристики речи, представленные MFCC-коэффициентами.

Модель учитывает обе модальности и формирует общее представление реплики, на основе которого решает две задачи классификации.

## 2. Используемый датасет

В проекте применяется **MELD (Multimodal EmotionLines Dataset)** — набор данных, содержащий диалоги из телесериала *Friends*, размеченные по эмоциям и тональности.

Источник: https://huggingface.co/datasets/declare-lab/MELD

Датасет содержит текстовые реплики, соответствующие видеофрагменты с аудиодорожками и аннотации.

### Классы эмоций

Модель определяет одну из семи эмоций:

| Эмоция | Описание |
|---|---|
| Anger | Злость |
| Disgust | Отвращение |
| Fear | Страх |
| Joy | Радость |
| Neutral | Нейтральное состояние |
| Sadness | Грусть |
| Surprise | Удивление |

### Классы тональности

| Класс | Описание |
|---|---|
| Positive | Положительная |
| Negative | Отрицательная |
| Neutral | Нейтральная |

### Используемая выборка

Используется **полный** MELD (в первой версии бралось только 1200/250/250 реплик, и качество упиралось в объём данных).

| Выборка | Количество реплик | Назначение |
|---|---:|---|
| Train | 9989 | Обучение модели |
| Development | 1109 | Валидация, выбор лучшей эпохи |
| Test | 2610 | Итоговая оценка модели |

Параметры `train_limit`, `dev_limit` и `test_limit` в `config.json` по-прежнему ограничивают выборки; значение `0` означает «весь сплит». Фактическое количество записей зависит от успешного декодирования аудиофайлов (несколько клипов MELD повреждены).

Текст и аудио сопоставляются по идентификаторам диалога (`Dialogue_ID`) и реплики (`Utterance_ID`).

## 3. Предобработка данных

Предобработка выполняется скриптом `prepare_data.py` во время сборки Docker-образа.

### Обработка текста

1. Из CSV-аннотаций загружаются тексты реплик и метки классов.
2. Типографские символы MELD (`’ “ ” — …`) приводятся к ASCII (`clean_text`). Раньше `company’s` разбивалось регуляркой на `company` + `s`.
3. Для каждой реплики сохраняются до 3 предыдущих реплик диалога («Speaker: text», без меток) в колонке `context`. Используются они только при `context_turns > 0`.
4. Текст токенизируется BPE-токенизатором RoBERTa (`max_length = 128`). Если задан контекст, подаётся пара «реплика + контекст», и при переполнении обрезается только контекст.
5. Строятся две маски: `attention_mask` (все реальные токены для энкодера) и `query_mask` (токены текущей реплики; они идут в Query cross-attention и в усреднение).

Если в `config.json` задать `"text_encoder": ""`, используется исходный вариант: регулярная токенизация, словарь 6000 слов и `nn.Embedding` с нуля.

### Обработка аудио

Аудиодорожки извлекаются из MP4-файлов с помощью FFmpeg. Для каждого аудиофрагмента вычисляются **MFCC (Mel-Frequency Cepstral Coefficients)** — кепстральные коэффициенты, характеризующие спектральные свойства речи.

Используемые параметры:

| Параметр | Значение |
|---|---|
| Частота дискретизации | 16000 Гц |
| Количество каналов | 1 (моно) |
| Длительность окна | 25 мс |
| Шаг окна | 10 мс |
| Оконная функция | Hann |
| Размер FFT | 512 |
| Количество Mel-фильтров | 40 |
| Количество MFCC | 20 (+ log-энергия) |
| Дельты | Δ и ΔΔ (окно ±2 кадра) |
| Pre-emphasis | 0.97 |
| Обрезка тишины | 35 дБ ниже максимума |
| Количество временных шагов | 64 |

Этапы вычисления признаков:

1. Извлечение аудиосигнала из MP4 (FFmpeg, 16 кГц, моно).
2. **Удаление DC-смещения и пиковая нормализация громкости** (громкость клипов MELD сильно различается).
3. **Pre-emphasis** `y[t] = x[t] − 0.97·x[t−1]`: усиливает высокие частоты речи.
4. Разбиение на окна 25 мс с шагом 10 мс и STFT.
5. **Обрезка тишины по краям**: отбрасываются начальные и конечные кадры, энергия которых на 35 дБ ниже максимума.
6. Mel-фильтры (40), логарифм, DCT-II, первые 20 MFCC.
7. **Log-энергия кадра**: признак громкости и интенсивности, важный для злости и радости.
8. **Δ и ΔΔ**: скорость и ускорение изменения признаков (динамика интонации).
9. **Приведение к 64 шагам усреднением по сегментам** вместо линейной интерполяции. Интерполяция брала только кадры у узлов и теряла остальные; теперь каждый шаг — среднее по своему участку записи.

Каждый аудиофрагмент представлен матрицей `(64, 63)`, где 63 = 3 × (20 MFCC + 1 энергия). Для train итоговый массив имеет форму `(≈9988, 64, 63)`.

Декодирование распараллелено по ядрам CPU (`--workers $(nproc)`). Во время `docker build` GPU недоступен, а узкое место здесь FFmpeg, а не вычисления. Полученные признаки сохраняются в `.npy`.

### Нормализация аудио

Перед обучением MFCC-признаки нормализуются по формуле:

`x_norm = (x - mean) / std`

Среднее значение и стандартное отклонение рассчитываются **только по обучающей выборке**, после чего применяются к train, dev и test.

Так предотвращается использование статистики тестовой выборки при подготовке обучающих данных.

## 4. Архитектура нейросети

Модель реализована в классе `CrossMTL` на основе `torch.nn.Module`.

Она содержит два входных блока, механизм перекрёстного внимания, общий скрытый слой и две классификационные головы.

### 4.1. Текстовая модальность

Токены проходят через предобученный **RoBERTa-base**, который дообучается вместе с моделью, а затем проецируются в размерность модели:

`RoBERTa(input_ids) → (32, 128, 768) → nn.Linear(768, 256) → (32, 128, 256)`

Слой `self.embedding` остаётся входом текстовой ветки, но теперь вместо таблицы эмбеддингов, обучаемой с нуля на 10 тыс. реплик, он получает контекстные представления предобученной языковой модели. Без этого текстовая ветка не выучивает семантику эмоций, и качество остаётся на уровне ~0.5.

### 4.2. Аудиомодальность

Аудиопризнаки обрабатываются полносвязным слоем, ReLU и Dropout, после чего добавляется обучаемое позиционное кодирование кадров (`audio_position`). Без него набор K/V для внимания неупорядочен:

`nn.Linear(63, 256) → nn.ReLU() → Dropout + audio_position`

Форма аудиотензора:

`(32, 64, 63) → (32, 64, 256)`

### 4.3. Cross-Attention

Для объединения модальностей применяется многоголовое перекрёстное внимание:

`nn.MultiheadAttention(embed_dim=256, num_heads=4, dropout=0.1, batch_first=True)`

Используется следующая схема:

- **Query (Q)** — текстовые представления.
- **Key (K)** — аудиопредставления.
- **Value (V)** — аудиопредставления.

```python
attended, weights = self.cross(
    text,
    sound,
    sound,
    need_weights=return_attention
)
```

Механизм позволяет каждому текстовому токену получать информацию из различных временных участков аудиосигнала.

В отличие от Self-Attention, где Q, K и V формируются из одной модальности, здесь запросы поступают из текста, а ключи и значения — из аудио.

Используются четыре головы внимания, что позволяет модели обучать несколько способов сопоставления текстовых и акустических признаков.

### 4.4. Фузирование модальностей

После Cross-Attention полученное аудиоконтекстное представление складывается с исходным текстовым представлением:

```python
fused = self.norm(text + attended)   # residual + LayerNorm
```

Затем применяется **Masked Mean Pooling** по токенам текущей реплики (`query_mask`):

```python
merged = (fused * mask).sum(1) / mask.sum(1).clamp(min=1)
```

Маска исключает из усреднения `<pad>`, служебные токены и токены контекста.

В результате последовательность текстовых токенов преобразуется в один мультимодальный вектор размерности 256 для каждой реплики.

Таким образом, в проекте используется **Cross-Attention с аддитивным объединением признаков**, а не обычная конкатенация текста и аудио.

### 4.5. Multi-Task Learning

После фузирования общее представление проходит через Shared Layer:

`Dropout → Linear(256, 256) → ReLU → Dropout`

Затем информация поступает в две независимые классификационные головы:

- **Emotion Head:** `Linear(256, 7)` — предсказание эмоции.
- **Sentiment Head:** `Linear(256, 3)` — предсказание тональности.

Общие слои обучаются сразу для обеих задач, а каждая классификационная голова имеет собственные параметры.

## 5. Обучение модели

Обучение реализовано в классе `Trainer`.

Используемые параметры по умолчанию:

| Параметр | Значение |
|---|---|
| Устройство | GPU (CUDA), смешанная точность (AMP fp16) |
| Количество эпох | 6 |
| Размер батча | 32 |
| Оптимизатор | AdamW, weight decay 0.01 |
| Learning Rate (новые слои) | 5e-4 |
| Learning Rate (RoBERTa) | 2e-5 |
| Расписание LR | linear warmup (10 %) + linear decay |
| Gradient clipping | 1.0 |
| Dropout | 0.1 |
| Функция потерь | CrossEntropyLoss |
| Hidden Size | 256 |
| Attention Heads | 4 |
| Random Seed | 42 |

### Процесс обучения

1. Загружаются подготовленные данные MELD.
2. Строится словарь токенов обучающей выборки.
3. Тексты, аудио и метки преобразуются в тензоры PyTorch.
4. MFCC нормализуются по статистике train.
5. Создаётся модель `CrossMTL`.
6. Данные перемешиваются и разбиваются на батчи.
7. Выполняется прямой проход через нейросеть.
8. Рассчитываются ошибки предсказания эмоции и тональности.
9. Вычисляется общая функция потерь.
10. С помощью Backpropagation и AdamW обновляются параметры модели.
11. После каждой эпохи модель оценивается на **dev**. Веса лучшей эпохи (по среднему weighted-F1 двух задач) сохраняются и используются для теста, так что test в выборе модели не участвует.

### Функция потерь

Для многозадачного обучения используется сумма двух функций Cross-Entropy:

`Loss = CrossEntropy(emotion) + CrossEntropy(sentiment)`

Таким образом, обе задачи участвуют в оптимизации общих слоёв модели, включая Cross-Attention.

## 6. Оценка результатов

После обучения модель переводится в режим оценки и тестируется на выборке `test`.

Для каждой задачи вычисляются следующие метрики:

- **Accuracy** — доля правильно классифицированных примеров.
- **Weighted-F1** — F1, взвешенная по числу примеров класса (основная метрика в статьях по MELD).
- **Macro-F1** — среднее значение F1-меры по всем классам с одинаковым весом каждого класса.
- **Confusion Matrix** — матрица ошибок классификации.

### Отчёт на localhost

После обучения формируется подробный отчёт `results/report.html`; его открывает встроенный HTTP-сервер (http://localhost:8000). Разделы отчёта:

- **Итоги**: accuracy, weighted-F1 и macro-F1 по обеим задачам, изменение относительно исходной версии, отметка о достижении цели 0.6.
- **Было / стало**: таблица и графики сравнения с сохранённым результатом исходной версии (`baseline_metrics.json`), включая F1 по каждому классу. Weighted-F1 и F1 по классам для старой версии восстанавливаются из её матрицы ошибок.
- **Что сделано**: перечень изменений по данным, аудио, тексту, модели, обучению и инфраструктуре.
- **Данные**: размеры выборок и распределение классов.
- **Предобработка аудио**: схема конвейера и визуализация признаков реального клипа (`audio_features.png`).
- **Архитектура**: схема модели.
- **Обучение**: гиперпараметры, устройство, время, кривые потерь (`loss.png`), метрики на dev по эпохам (`dev_metrics.png`) и таблица эпох.
- **Тест**: precision, recall и F1 по классам, нормированные матрицы ошибок (`confusion.png`).
- **Cross-modal attention**: карта внимания с подписями токенов (`attention.png`).

Сырые данные доступны по адресам `/metrics` (метрики теста) и `/history` (метрики по эпохам).

## 8. Запуск проекта

### Требования

Для запуска необходимы:

- Docker с поддержкой BuildKit;
- доступ к интернету при первоначальной сборке;
- NVIDIA GPU с драйвером и NVIDIA Container Toolkit (в Docker Desktop/WSL2 есть по умолчанию). Без GPU код работает и на CPU, но гораздо медленнее;
- достаточное свободное место на диске для скачивания и обработки MELD.

Установка Python, PyTorch и FFmpeg на основной компьютер не требуется, поскольку зависимости устанавливаются внутри Docker-образа.

### Шаг 1. Сборка Docker-образа

В терминале перейдите в папку проекта и выполните:

```bash
sudo DOCKER_BUILDKIT=1 docker build --progress=plain -t meld-mtl .
```

Во время первой сборки Docker:

1. Устанавливает необходимые библиотеки (PyTorch с CUDA) и FFmpeg.
2. Скачивает веса RoBERTa-base, чтобы запуск не требовал интернета.
3. Загружает оригинальный архив MELD и CSV-аннотации.
4. Извлекает аудиофрагменты из MP4.
5. Вычисляет аудиопризнаки.
6. Сохраняет подготовленные файлы внутрь Docker-образа.

**Важно:** исходный архив MELD занимает приблизительно 10.9 ГБ. Первая сборка может продолжаться достаточно долго в зависимости от скорости интернета и производительности компьютера.

Для повторных сборок применяется BuildKit-кэш, позволяющий повторно использовать скачанный архив. Если изменяются настройки или код предобработки, MFCC могут вычисляться заново.

### Шаг 2. Создание папки результатов

```bash
mkdir -p results
```

### Шаг 3. Запуск контейнера

```bash
sudo docker run --rm --gpus all -p 8000:8000 \
  -v "$(pwd)/results:/app/results" \
  meld-mtl
```

Флаг `--gpus all` даёт контейнеру доступ к GPU. В логе первой строкой выводится используемое устройство, например `Device: cuda (NVIDIA GeForce RTX 3060)`.

При использовании стандартного режима `serve` программа выполняет обучение, формирует результаты и запускает HTTP-сервер.

### Запуск из PowerShell (Windows + Docker Desktop)

В PowerShell нет `sudo`, а путь `\\wsl.localhost\...` нельзя передать в `-v`. Поэтому контейнер запускается без монтирования, а результаты копируются командой `docker cp`:

```powershell
docker build --progress=plain -t meld-mtl .
docker run --gpus all -p 8000:8000 --name meld-run meld-mtl
# во втором окне, пока контейнер работает:
docker cp meld-run:/app/results C:\meld_results
# после завершения:
docker rm -f meld-run
```

### Шаг 4. Просмотр результатов

Откройте в браузере:

http://localhost:8000

Результаты сохраняются в локальной папке `results/`, подключённой к контейнеру.


Изменять параметры обучения можно через аргументы командной строки.

Например, запуск на 3 эпохи с размером батча 16:

```bash
sudo docker run --rm --gpus all -p 8000:8000 \
  -v "$(pwd)/results:/app/results" \
  meld-mtl python main.py --mode serve --epochs 3 --batch-size 16
```

Для изменения скорости обучения:

```bash
sudo docker run --rm --gpus all -p 8000:8000 \
  -v "$(pwd)/results:/app/results" \
  meld-mtl python main.py --mode serve --learning-rate 0.0005
```

Доступны также `--encoder-learning-rate`, `--context-turns` и `--seed`.

Параметры `train_limit`, `dev_limit`, `test_limit`, `audio_steps` и `n_mfcc` влияют на подготовленные данные, поэтому их изменение требует повторной сборки Docker-образа.

Изменение локального `config.json` после сборки само по себе не изменяет уже скопированный внутрь образа файл.

## 10. Особенности реализации

- Используется реальное аудио из MELD, а не искусственно сгенерированные аудиопризнаки.
- Для акустического представления применяется MFCC без предобученных речевых энкодеров.
- Cross-Attention реализован с помощью `nn.MultiheadAttention` с текстовыми Query и аудио Key/Value.
- Используется аддитивное объединение мультимодальных признаков.
- Две задачи обучаются совместно с общей функцией потерь.
- Статистика нормализации аудио рассчитывается только по обучающей выборке.
- Программа разделена на независимые компоненты подготовки данных, архитектуры, обучения и HTTP-сервиса.
- Для веб-сервера применяется стандартная библиотека Python без Flask и FastAPI.
- Сборка и запуск проекта выполняются через Docker.

## 11. Ограничения

Проект представляет собой учебную реализацию мультимодальной классификации.

Основные ограничения:

- Обучение выполняется на сокращённой выборке MELD.
- MFCC отражают спектральные характеристики речи, но не заменяют полноценные предобученные аудиоэнкодеры.
- Небольшое количество эпох и ограниченный объём данных могут снижать качество классификации.
- Модель использует текстовые и аудиопризнаки отдельных реплик и не моделирует явно весь контекст диалога.
- Большой размер исходного архива MELD увеличивает время первоначальной сборки.
- Качество модели зависит от корректности исходных аннотаций и аудиозаписей.

Проект демонстрирует основные этапы разработки системы глубокого машинного обучения: подготовку данных, извлечение признаков, построение мультимодальной архитектуры, совместное обучение, оценку качества и контейнеризацию.
